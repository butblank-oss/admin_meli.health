## 3. 발견 사항

### F-1. 원문 열람 중 목록이 다시 그려지면 오류 — **수정함**

**재현**: 열람 모달을 연 상태에서 목록이 재렌더되면 대상 행(`tr`)이 DOM에서 떨어져 나감.
확인을 누르면 `Cannot read properties of null (reading 'p')`로 스크립트가 죽음.

**조치**: `assets/js/views-people.js`에 방어 코드 1줄 추가. 대상 행이 살아있지 않으면 모달을 닫고
`목록이 새로고침되어 다시 시도해야 해요` 안내를 띄움.

```js
if(!revC||!revC.tr||!revC.tr.isConnected){closeAll();toast('목록이 새로고침되어 다시 시도해야 해요','wa');return}
```

> 정상 조작으로는 잘 닿지 않는 경로지만, 30초 자동 재마스킹 타이머가 떨어진 노드를 붙들고 있어 손대는 편이 안전합니다.

### F-2. 판정 기준표와 실제 등급 계산이 다름 — **정책 결정 필요**

`활동 현황 → 판정 기준` 탭의 표와 `core.js`의 `TESTS` 등급 함수가 어긋납니다.

| 검사 | 판정 기준 탭 | 실제 코드 |
|---|---|---|
| GDS-SF | 0–5 / 6–9 / 10+ | 동일 ✅ |
| ISI-K | 0–7 / 8–14 / 15–21 / 22+ | 15 이상을 `중등도` 하나로 합침 ❌ |
| PSS | 0–13 / 14–16 / 17–18 / 19+ | 17 이상을 `높음` 하나로 합침 ❌ |
| SMCQ | 표에 없음 | 0–5 정상 / 6+ 주의로 동작 중 ❌ |

또한 PSS 만점이 코드상 **30점**입니다. 판정 기준 탭은 10문항이라 적고 있는데,
PSS-10은 문항당 0–4점이라 만점이 **40점**이어야 합니다.

**위험**: 이 등급이 `먼저 연락해볼 분들`의 위험군 자동 선별에 그대로 쓰입니다.
기준이 틀리면 연락해야 할 어르신이 목록에서 빠집니다. → 정책 정의서 **OP-2**

### F-3. 새 열람 기록이 목록 아래로 묻힘

`addAudit()`이 날짜는 `2026-08-21`로 고정하고 시각만 브라우저 현재 시각을 씁니다.
새벽에 조작하면 `2026-08-21 01:41`이 되어, 기존 시드 데이터(`14:22`)보다 아래로 정렬됩니다.

기록은 정상 적재되므로 프로토타입 시연에는 지장이 없습니다.
실서비스에서는 **서버 시각**을 쓰면 사라지는 문제입니다.

### F-4. 모바일에서 가로 스크롤 발생

390px 폭에서 문서 폭이 551px로 넘칩니다. 사이드바 240px 고정 + 테이블 최소폭 때문입니다.
반응형 대응이 원래 없는 데스크톱 전용 설계입니다. 보건소 PC에서 쓰는 도구라면 그대로 둬도 됩니다.
→ 확인 필요 (아래 "물어볼 것" 3번)

### F-5. 아이콘 전용 버튼에 대체 텍스트 없음

페이지네이션 화살표, 모달 닫기 `✕` 등 4개 버튼에 텍스트도 `aria-label`도 없습니다.
스크린리더에서 "버튼"으로만 읽힙니다. 공공기관 납품이라면 웹접근성 심사에 걸릴 수 있습니다.

같은 맥락에서 `<h1>`이 0개입니다. 화면 제목이 `<div class="ttl">`로 되어 있습니다.

### F-6. 화면에 흩어진 수치가 서로 안 맞음

시드 난수로 만든 더미 데이터라 개별 참여자 안에서 앞뒤가 안 맞는 경우가 있습니다.
예: 어떤 참여자는 `연속 출석 1일`인데 7월 출석 챌린지는 `18/15일 성공`.

시연 중 "이 숫자 왜 이래요?" 질문이 나올 수 있는 지점입니다.
실데이터로 바꾸면 사라지지만, 시연 전이라면 눈에 띄는 항목만 손볼 수 있습니다.

### F-7. 조작 결과가 새로고침하면 사라짐

승인·탈퇴·푸시 예약·열람 기록이 전부 메모리에만 남습니다. 서버가 없으니 당연한 동작입니다.
시연 자리에서 새로고침하면 처음으로 돌아간다는 점만 공유해두면 됩니다.

## 4. 성능

실측값입니다 (gzip 적용 후 기준).

| 항목 | 원본 | 현재 |
|---|---|---|
| 파일 크기 (raw) | 350KB | 302KB |
| **첫 로드 전송량** | 196KB | 200KB — **사실상 동일** |
| **재방문 전송량** | 196KB (매번 전부) | **3.2KB** (HTML만, 나머지 캐시) |
| 외부 의존성 | 없음 | 없음 (동일) |

첫 로드는 나아지지 않았습니다. 원본의 base64 폰트가 gzip으로 대부분 회수되기 때문입니다.
실제 이득은 **재방문**에 있습니다. 폰트 150KB와 JS·CSS가 캐시되어 196KB → 3.2KB로 떨어집니다.
매일 같은 화면을 여는 채널관리자에게는 이쪽이 체감되는 차이입니다.
