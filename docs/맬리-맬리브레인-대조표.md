## 0. 이 문서를 읽는 법

이 문서는 **두 제품 중 어느 쪽이 더 낫다**를 가리는 문서가 아닙니다.
조사해 보니 **서로 앞선 데가 달랐습니다.** 그래서 한 방향 이식표가 아니라 양방향입니다.

- **2장**은 사실 관계입니다. 추측과 확인을 구분해 적었습니다.
- **5장**이 실제 작업 목록입니다. 개발 논의는 여기서 시작하면 됩니다.
- **6장 `[확인 필요]`** 는 제가 번들만으로는 판단할 수 없던 것입니다. 이 여덟 가지 답에 따라
  1차 범위가 달라집니다. **가장 먼저 답을 주셔야 하는 부분입니다.**

항목 번호는 고정입니다. `B-03`, `M-01` 처럼 불러 주세요.

### 4.3.1 파트너(병원) 쪽 통제 — 사내 가이드로 확인

## 6. `[확인 필요]` — 먼저 답이 필요한 것

번들로는 판단할 수 없었습니다. **답에 따라 1차 범위가 달라집니다.**

| 번호 | 질문 | 왜 번들로 안 되나 | 답이 "없음"이면 |
|---|---|---|---|
| `C-01` | 맬리에 **자동 재마스킹**이 있나? | 타이머 흔적을 못 찾음. 캡처에 회원 상세 청크가 없음 | `M-01` 1차 |
| `C-02` | 맬리에 **세션 유휴 자동 차단**이 있나? | 〃. `로그아웃`은 메뉴 버튼뿐 | `M-02` 1차 · **고시 위반** |
| `C-03` | 맬리에 **비밀번호 연속 실패 잠금**이 있나? | 서버 로직. (`잠금` 히트는 전부 **엑셀 파일 잠금**이었음) | `M-03` 1차 · **고시 위반** |
| `C-04` | 맬리가 **접속기록을 정기 점검**하나? | 그런 화면이 메뉴에 없음. 사내 절차일 수 있음 | `M-04` 1차 · **고시 위반** |

> 캡처된 청크에 해당 라우트가 없었기 때문입니다.

## 7. 합칠 때 — 권한·로그를 같은 체계로

"합친다 — 권한·로그를 같은 체계로" 로 정해졌으므로, 지금 결정해 둘 것.

### 7.1 권한 코드

맬리는 `/adm` ↔ `/mng` 쌍으로 이미 갈라 두었습니다 —
`MELI_MEMBERS` ↔ `MELI_MANAGER_MEMBERS`, `MELI_NFC` ↔ `MELI_MANAGER_NFC` 등.

맬리브레인도 **같은 규칙**을 따릅니다. 새 접두사를 만들지 말고 기존 책에 맞춥니다.

```
MELI_CARE_PARTICIPANTS   ↔  MELI_MANAGER_CARE_PARTICIPANTS
MELI_CARE_APPLICATIONS   ↔  MELI_MANAGER_CARE_APPLICATIONS
MELI_CARE_CONSULT        ↔  MELI_MANAGER_CARE_CONSULT
MELI_CARE_REPORT         ↔  MELI_MANAGER_CARE_REPORT
MELI_CARE_AUDIT          ↔  MELI_MANAGER_CARE_AUDIT
```

역할도 맬리 7종(`system` `masterAdmin` `serviceAdmin` `contentsAdmin` `manager`
`doctor` `classManager`)에 맞춥니다. 케어센터 주무관 = `manager`,
주/부 구분은 역할이 아니라 **(사람 × 그룹) 좌석 속성**으로 둡니다.

### 7.2 열람 로그

한 테이블로 합치려면 **사유 코드가 같아야** 합니다.

- 공통 8종은 맬리 것을 그대로 (`정책-정의서.md` §2.2)
- 케어센터 4종(미활동자 안부 연락 / 위험군 상담 연계 / 참여 신청 확인 / 보건소 공문 회신)은
  **같은 테이블에 제품 구분자와 함께** 둡니다. 별도 테이블을 만들지 않습니다.
- 보관 기간은 **2년**으로 통일합니다. 둘 다 민감정보입니다.

### 7.3 API 경로

맬리 규칙을 그대로 씁니다 — 슈퍼 `/adm/*`, 채널 `/mng/*`.
같은 응답 스키마를 쓰고 **서버가 토큰 보고 범위를 자릅니다.** 화면은 한 벌로 끝납니다.
