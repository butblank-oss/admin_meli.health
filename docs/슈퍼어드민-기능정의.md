# 슈퍼어드민 기능 정의서

원메딕스 **운영팀**이 쓰는 플랫폼 관리 콘솔입니다.
채널 어드민(치매안심센터용)과는 **별개 시스템**이며, 사용자·권한·화면이 겹치지 않습니다.

---

## 범위를 어떻게 잘랐나

슈퍼어드민의 기능은 추측이 아니라 **채널 어드민에서 이미 드러난 것**에서 도출했습니다.
근거가 화면에 남아 있으니 기획 논쟁 없이 확정할 수 있습니다.

### 근거 1 — 채널 어드민이 "못 한다"고 말한 것

| 채널 어드민 화면의 문구 | → 슈퍼어드민의 기능 |
|---|---|
| "채널관리자는 일정을 **확인만** 할 수 있어요" (사이드바 `읽기 전용`) | **프로그램 일정 편성** |
| "변경 요청과 처리 결과는 기록에 남아요" | **일정 변경 요청 처리 큐** |
| "채널 배정은 **원메딕스 운영팀이 관리**해요" | **채널·계정 관리** |
| "3일 넘게 답변이 없으면 **운영팀에 자동으로 알림**이 가요" | **상담 에스컬레이션 큐** |
| "확인이 필요한 항목 — **운영팀 회신 대기 중**" (판정 기준 탭) | **문의·이슈 처리 큐** |
| "데이터는 매일 새벽 3시에 갱신돼요" | **배치 모니터링** |

### 근거 2 — 채널 하나로는 답이 안 나오는 것

- 채널 어드민은 **자기 기관 822명**만 봅니다. 기관 간 비교, 전체 추세, 미달 기관 조기 경보는 볼 수 없습니다.
- 검사 등급 기준(P-15)은 **전 채널 공통**이어야 합니다. 채널마다 다르면 통계가 깨집니다.
- 콘텐츠(두뇌훈련 8종·마음다루기 4종·운동 4루틴·검사 4종)는 한 곳에서 만들어 전 채널에 뿌립니다.

## 기능 목록 — 4개 영역 14개 기능

우선순위 표기: **P0** 없으면 운영 불가 / **P1** 곧 필요 / **P2** 나중

### A. 채널 운영 (P0)

| # | 기능 | 하는 일 |
|---|---|---|
| A-1 | **채널 목록·상세** | 기관 등록, 기본정보, 담당자, 계약 기간. 채널 어드민의 `채널 전환` 모달이 여기서 나온 데이터를 읽음 |
| A-2 | **기수 관리** | 기수 개설(대상자 배정) → 진행 → 종료. 종료 시 참여자를 `만료`로 일괄 전환. 현재 1기 230명 / 2기 714명 / 3기 822명 |
| A-3 | **계정·권한** | 채널관리자 계정 발급·정지, 채널 배정, 역할 부여. 퇴사자 즉시 차단이 핵심 |
| A-4 | **채널 비교** | 기관별 참여율·이탈률·수행률 나란히. **미달 기관 조기 경보**가 실질 목적 |

### B. 프로그램·콘텐츠 (P0~P1)

| # | 기능 | 하는 일 |
|---|---|---|
| B-1 | **일정 편성** (P0) | 채널×날짜별 활동 배정. 채널 어드민이 읽기 전용으로 보는 그 화면의 원본 |
| B-2 | **일정 변경 요청 처리** (P0) | 채널에서 올라온 요청(활동 교체/휴강/추가) 승인·반려 + 사유 회신 |
| B-3 | **콘텐츠 관리** (P1) | 두뇌훈련·마음다루기·운동 루틴 CRUD. 운동은 **동작 단위**까지 (세트·횟수·주의사항) |
| B-4 | **검사·판정 기준 관리** (P0) | 검사 등급 구간의 **유일한 편집 지점**. 여기서 바꾸면 전 채널에 반영 |
| B-5 | **챌린지 관리** (P1) | 챌린지 개설, 기준(일수·횟수·걸음), 대상 채널, 주말 규칙 |

### C. 감사·보안 (P0)

| # | 기능 | 하는 일 |
|---|---|---|
| C-1 | **전체 열람 기록** (P0) | 전 채널 통합. 채널 어드민은 자기 것만 봄 |
| C-2 | **이상 열람 탐지** (P0) | **가장 중요.** 특정 담당자가 단시간에 과도하게 원문을 열람하거나, 심야 열람, 대량 다운로드를 잡아냄. 개인정보 유출은 보통 권한 있는 내부자에서 시작 |
| C-3 | **정책 설정** (P1) | 마스킹 규칙, 자동 재마스킹 시간(현재 30초), 열람 사유 목록, 로그 보관 기간, 푸시 발송 가능 시간대(현재 9–18시) |

### D. 플랫폼 (P1~P2)

| # | 기능 | 하는 일 |
|---|---|---|
| D-1 | **배치 모니터링** (P1) | 새벽 3시 집계 성공/실패, 지연 알림. 실패하면 전 채널 숫자가 어제 것 |
| D-2 | **앱 버전 관리** (P2) | 버전 분포(현재 4.0.7~3.4.0), 강제 업데이트 기준, 구버전 사용자 안내 |

## 채널 어드민과 겹치지 않게 자르는 규칙

같은 데이터를 두 어드민이 보지만 **할 수 있는 일이 다릅니다.** 이 경계가 흐려지면 사고가 납니다.

| 대상 | 채널 어드민 | 슈퍼어드민 |
|---|---|---|
| 참여자 | 자기 기관만. 조회·수정·탈퇴 | 전 채널 조회. **개별 수정은 안 함** (책임 소재를 채널에 둠) |
| 개인정보 원문 | 사유 남기고 열람 | **열람하지 않음.** 열람 *기록만* 감시 |
| 일정 | 읽기 전용 | 편성 |
| 검사 등급 기준 | 읽기 전용 | 편집 |
| 열람 기록 | 자기 채널 | 전 채널 + 이상 탐지 |

**규칙 S-1 — 슈퍼어드민은 개인정보 원문을 보지 않는다**
조건: 운영팀이 참여자 목록을 조회한다
동작: 항상 가린 상태로만 보인다. 원문 열람 기능 자체가 없다
예외: 없음. 감시하는 쪽이 감시 대상 권한을 함께 가지면 감사 체계가 무의미해진다

> 이건 편의보다 감사 무결성을 택한 설계입니다. 운영팀이 원문을 봐야 하는 상황(앱 오류 문의 회신 등)이
> 실제로 있다면 별도 승인 절차를 붙여야 하고, 그건 정책 결정 사항입니다 → **SP-1**

## 미결 정책 (슈퍼어드민 신규)

| # | 항목 | 정해야 할 것 |
|---|---|---|
| **SP-1** | 운영팀의 원문 열람 | 아예 막을 것인가, 2인 승인 등 별도 절차로 허용할 것인가 |
| **SP-2** | 이상 열람 판정 기준 | 몇 건/몇 분이면 이상인가. 심야는 몇 시부터인가. 오탐이 많으면 아무도 안 봄 |
| **SP-3** | 기수 종료 처리 | 종료 시 참여자를 자동 `만료` 전환할 것인가, 확인 후 수동인가. 진행 중 챌린지는 어떻게 |
| **SP-4** | 판정 기준 변경 소급 | 등급 구간을 바꾸면 **과거 검사 결과의 등급도 다시 계산**할 것인가. 이미 제출한 보건소 리포트와 어긋남 |
| **SP-5** | 콘텐츠 배포 단위 | 전 채널 일괄인가, 채널별 선택인가. 채널마다 다르면 비교 지표가 깨짐 |
| **SP-6** | 계정 정지 시점 | 퇴사 통보 즉시인가, 인수인계 후인가. 담당자 없는 채널의 상담 SLA는 누가 책임지나 |

**SP-4가 가장 위험합니다.** 검사 등급 기준을 한 번 바꾸면 과거 리포트와 숫자가 달라집니다.
보건소에 이미 제출한 자료와 어긋나면 해명해야 합니다.
→ 기준에 **적용 시작일(버전)** 을 두고, 과거 데이터는 당시 기준으로 유지하는 쪽을 권합니다.
