# 맬리 케어센터 채널 어드민 — 정책 정의서

프로토타입 코드에 **이미 구현되어 있는 규칙**과, 실서비스 전에 **확정이 필요한 항목**을 나눠 정리했습니다.
"확정됨"은 프로토타입이 그렇게 동작한다는 뜻이지 보건소와 합의됐다는 뜻은 아닙니다.

- 기준 문서: 업로드 프로토타입 (2026-08-21 기준 데이터)
- 화면상 컨텍스트: 인천 남동구 치매안심센터 3기 / 171일째 / 대상자 822명

---

## 1. 권한

### 1.1 역할 구분 (확정됨)

| 역할 | 소속 | 프로토타입에서의 권한 |
|---|---|---|
| 채널관리자 | 치매안심센터 (예: 김주무) | 참여자 조회·수정·탈퇴, 신청 승인, 푸시 발송, 리포트 생성, 원문 열람 |
| 운영팀 | 원메딕스 (예: 이운영) | 채널 배정, 프로그램 일정 편성, 일정 변경 요청 처리 |

**규칙 P-1 — 일정 편집 금지**
조건: 채널관리자가 프로그램 일정 화면에 진입한다
동작: 조회만 가능하다. 사이드바에 `읽기 전용` 표시가 붙는다
예외: `일정 변경 요청` 모달로 대상일·유형(활동 교체/휴강 처리/활동 추가)·사유를 보내면 운영팀이 처리한다. 요청과 결과는 기록에 남는다

**규칙 P-2 — 채널 배정**
조건: 채널관리자가 채널 전환을 시도한다
동작: 배정된 채널만 목록에 뜬다. 현재는 1개뿐이다
예외: 배정 자체는 운영팀만 한다. 새 기관이 추가되면 계정에 자동으로 나타난다

## 2. 개인정보 보호

가장 촘촘하게 설계된 영역입니다. 보건소 관리·감독 점검표의 **접속기록 보관** 항목 증빙과 직접 연결됩니다.

### 2.1 기본 마스킹 (확정됨)

**규칙 P-3 — 항상 가린 상태가 기본**
조건: 참여자 이름·전화번호가 화면에 표시된다
동작: 이름은 가운데 글자를 `*`로(`김*순`), 전화번호는 뒷 4자리만(`010-****-1234`) 표시한다
예외: 없음. 원문은 아래 P-4를 거쳐야만 보인다

### 2.2 원문 열람 (확정됨)

**규칙 P-4 — 사유 없이는 열람 불가**
조건: 참여자 행의 `보기` 버튼을 누른다
동작: 사유 선택 모달이 뜬다. 사유를 고르지 않고 확인을 누르면 `사유를 선택해야 열람할 수 있어요`가 뜨고 진행되지 않는다
예외: 없음. 이것이 P-4의 핵심이다

사유 선택지 (5종, 프로토타입 하드코딩):
`미활동자 안부 연락` / `위험군 상담 연계` / `앱 오류 문의 회신` / `참여 신청 확인` / `보건소 공문 회신`

**규칙 P-5 — 30초 자동 재마스킹**
조건: 원문 열람이 승인됐다
동작: 해당 행 배경이 노란색으로 바뀌고 원문이 노출된다. **30초 후 자동으로 다시 가려진다**
예외: 사용자가 `가리기` 버튼으로 즉시 되돌릴 수 있다

**규칙 P-6 — 열람 기록 적재**
조건: 원문 열람, 명단 내려받기, 탈퇴 처리, 푸시 예약, 리포트 생성, 신청 일괄 처리가 일어난다
동작: 일시·담당자·소속·행위·대상 건수·사유·접속 위치(IP 부분 마스킹)를 열람 기록에 남긴다. **2년간 보관**한다
예외: 없음. `사유 없이 열람 0건`이 화면의 KPI로 노출된다

### 2.3 명단 내려받기 (확정됨)

**규칙 P-7 — 가린 상태가 기본값**
조건: 명단 내려받기 모달을 연다
동작: `가린 상태 (권장)`이 기본 선택이다
예외: `원문 포함`을 고르면 사유 입력이 필요하다는 안내로 바뀐다

## 3. 참여자 상태

### 3.1 회원 상태 (확정됨)

```
[참여 중 active] ──탈퇴 처리──> [회원탈퇴 withdrawn]   (되돌릴 수 없음)
       │
       ├──중도 이탈──> [중도포기 dropped]
       └──기수 종료──> [만료 expired]
```

### 3.2 활동 상태 (확정됨 · 회원 상태와 별개 축)

마지막 활동 이후 경과일로 판정합니다.

| 구간 | 라벨 | 표시 |
|---|---|---|
| 활동 이력 없음 | 무활동 | — |
| 0–7일 | 최근 활동 | — |
| 8–14일 | 7일 무활동 | 주의 |
| 15일 이상 | 14일+ 무활동 | **활동 중단** (주황) |

> 라벨과 실제 구간이 어긋나 보입니다. `7일 무활동` 라벨이 실제로는 8~14일 구간입니다. → **OP-9**

### 3.3 탈퇴 (확정됨)

**규칙 P-8 — 이중 확인 없이는 탈퇴 불가**
조건: 탈퇴 처리 모달을 연다
동작: **사유 선택**과 **`위 내용을 확인했어요` 체크**가 모두 충족돼야 버튼이 활성화된다
예외: 이미 탈퇴 상태인 대상은 자동으로 제외된다. 대상이 0명이면 `탈퇴 처리할 대상이 없어요`로 막는다

사유 선택지: `본인 요청` / `연락 두절` / `타 지역 전출` / `중복 계정`

**규칙 P-9 — 탈퇴는 즉시·비가역**
조건: 탈퇴가 확정된다
동작: 앱 이용이 즉시 차단된다. 되돌릴 수 없다 (되돌리기 수단이 실제로 없음 — 안내와 동작이 일치함)
예외: 없음

> 대비: 신청 일괄 처리와 푸시 예약은 6초짜리 `되돌리기` 토스트를 줍니다. 탈퇴만 유예가 없습니다.
> 탈퇴 이후 개인정보를 언제 파기하는지는 정해져 있지 않습니다 → **OP-10**

## 4. 참여 신청

### 4.1 상태 흐름 (확정됨)

```
[대기 pending] ──승인──> [승인 approved]
      │  ↑         └──거절──> [거절 rejected]
      │  └────────────────────────┘  (대기로 되돌리기)
      └──보류──> [보류 hold] ──승인/거절──> ...
```

`보류`는 확인이 필요한 건을 잠시 빼두는 상태입니다 (주소 확인 필요, 본인 확인 대기, 기관 배정 협의 중).

### 4.2 ⚠️ 승인과 앱 가입이 분리되어 있음

**이것은 프로토타입 스스로가 빨간색 경고로 표시한 항목입니다.**

> "지금은 승인 여부와 상관없이 앱에 가입할 수 있어요. 대기 111건 중 27명, 거절 27건 중 15명이 이미 가입해서 활동 중이에요. 승인을 앱 사용 조건으로 걸지 보건소와 정해야 해요."

현재 상태:
- 대기 111건 → 그중 **27명이 이미 앱에서 활동 중**
- 거절 27건 → 그중 **15명이 이미 앱에서 활동 중**
- 승인 1,227건 → 그중 **37명은 승인됐는데 앱 미설치**

→ **OP-1**. 어드민의 승인 절차가 현재 아무것도 통제하지 못하고 있습니다.

## 5. 위험군 자동 선별

### 5.1 무활동 판정 (확정됨)
7일 → 주의 / 14일 → 위험

### 5.2 검사 등급 (확정됨 · 표준 척도)

**결정 완료.** 화면의 `판정 기준` 탭과 실제 등급 코드가 어긋나 있던 문제를
**표준 척도 기준으로 확정**하고 코드를 맞췄습니다.

| 검사 | 문항 | 만점 | 등급 구간 |
|---|---|---|---|
| 우울 GDS-SF | 15문항 | 15 | 정상 0–5 / 주의 6–9 / **위험 10–15** |
| 불면 ISI-K | 7문항 | 28 | 정상 0–7 / 주의 8–14 / 중등도 15–21 / **심각 22–28** |
| 스트레스 PSS | 10문항 | 40 | 정상 0–13 / 주의 14–16 / 높음 17–18 / **매우 높음 19–40** |
| 기억감퇴 SMCQ | 14문항 | 14 | 정상 0–5 / **주의 6–14** |

**규칙 P-15 — 기준표는 하나의 출처에서만 나온다**
조건: `활동 현황 → 판정 기준` 탭이 그려진다
동작: 표의 등급 구간을 **실제 등급 판정 함수에서 계산해 그린다**. 별도로 적어두지 않는다
예외: 없음 — 표만 고치고 판정은 그대로인 사고를 구조적으로 막기 위한 규칙이다

> 실서비스에서도 이 원칙을 유지해야 합니다. 등급표를 문서·화면·코드 세 곳에 각각 적으면
> 반드시 어긋나고, 어긋나도 아무도 모릅니다.

### 5.3 프로토타입이 이미 적어둔 미결 항목

`판정 기준` 탭 하단에 "운영팀 회신 대기 중"으로 표시된 3건:
- 노력 점수는 계산되지만 랭킹 총점에 반영되지 않음 → **OP-3**
- 음주(AUDIT-K)는 아직 검사 목록 자체에 없음 → **OP-4**
- 터그테스트는 점수가 전송되지 않아 등급 산출 불가 → **OP-5**

## 6. 지표 정의 (확정됨)

`활동 현황 → 판정 기준` 탭 기준입니다. 보건소 제출 수치와 대조할 때의 기준선입니다.

| 지표 | 세는 대상 | 계산식 |
|---|---|---|
| 대상자 수 | 기수에 배정된 전원 | `audienceCount` |
| 참여자 수 | 해당 월 참여 상태 유지자 | `participantCount` |
| 활동자 수 | 해당 월 1회 이상 활동 | `activistCount` |
| 누적 중도포기 | 참여 상태 = 종료(T) | `abandonerCount` |
| 수행률 | 추천받은 활동 중 수행 비율 | 활동수 ÷ 추천수 |
| 랭킹 점수 | 월 단위 총점 (최대 1000) | `600×(활동÷추천) + 400×(연속일÷추천일)` |
| N | 오늘 수행한 활동 수 | `todayActivityCount` |
| PIN | 전화 응대용 조회번호 | `vocNumber` |

## 7. 챌린지 (확정됨)

**규칙 P-10 — 달성 판정**
- 출석형: **평일에** 하루 활동 `per`회 이상 → 그날 달성. 주말은 판정 대상에서 제외(`out`)
- 걷기형: 하루 걸음 수가 `per`보 이상 → 그날 달성. **요일 구분 없음**
- 기간 내 달성일이 `crit`일 이상이면 챌린지 성공

| 챌린지 | 유형 | 기준 | 상태 |
|---|---|---|---|
| 7월 출석 챌린지 | 출석 | 하루 2회 × 15일 | 진행 중 (296명 참여 / 66명 성공) |
| 7월 걷기 챌린지 | 걷기 | 하루 3,000보 × 20일 | 진행 중 (550명 / 171명) |
| 6월 출석 챌린지 | 출석 | 하루 2회 × 14일 | 완료 (284명 / 71명) |
| 8월 걷기 챌린지 | 걷기 | 하루 3,000보 × 20일 | 예정 |

> 출석형만 주말을 빼고 걷기형은 빼지 않습니다. 의도된 것인지 확인 필요 → **OP-6**

## 8. 푸시 메시지 (확정됨)

**규칙 P-11 — 발송 가능 시간대**
조건: 메시지를 예약한다
동작: **오전 9시 ~ 오후 6시**에만 나간다
예외: 시간대 밖으로 예약하면 **다음 날 오전 9시로 자동 이동**한다

**규칙 P-12 — 수정 가능 시점**
조건: 예약된 메시지를 고치거나 취소한다
동작: **발송 30분 전까지** 가능하다
예외: 취소해도 기록에는 남는다

발송 방식: `푸시 + 알림함` / `푸시만` / `알림함만`
발송 유형: 지금 바로 / 시간을 정해 예약 / 매주 같은 시각에 반복

## 미결 정책 11건 (1건 해소)

실서비스 전에 확정이 필요한 항목입니다. 우선순위순입니다.
**OP-2는 해소**됐고, 별도로 다음 3건이 결정됐습니다.

| 결정 항목 | 결정 내용 |
|---|---|
| 검사 등급 기준 | **표준 척도 채택.** 코드를 맞추고 기준표를 코드에서 파생시킴 |
| 지원 화면 폭 | **데스크톱 전용.** 기관 PC 기준, `min-width: 1200px` |
| 웹접근성 | **납품 대상.** WCAG 2.1 AA 자동 검사 위반 0건까지 대응 완료 |

| # | 항목 | 왜 문제인가 | 정해야 할 것 |
|---|---|---|---|
| **OP-1** | 승인 ↔ 앱 가입 연결 | 대기 111건 중 27명, 거절 27건 중 15명이 이미 앱 사용 중. 승인 절차가 무력화됨 | 승인을 앱 사용의 **선행 조건**으로 걸 것인가? 이미 활동 중인 거절자 15명은 어떻게 할 것인가? |
| ~~OP-2~~ | ~~검사 등급 기준 불일치~~ | **해소됨** — 표준 척도로 확정하고 코드를 맞춤. 기준표는 이제 코드에서 파생됨 (5.2 참고) | — |
| **OP-3** | 노력 점수 미반영 | 계산은 되는데 랭킹 총점에 안 들어감 | 반영할 것인가, 지표에서 뺄 것인가 |
