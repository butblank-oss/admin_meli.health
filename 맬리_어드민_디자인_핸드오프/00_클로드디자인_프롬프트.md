# Claude Design에 붙여넣을 프롬프트

> 아래 `▼ 여기서부터` 부터 `▲ 여기까지` 사이를 **그대로 복사**해서 Claude Design에 붙여넣고,
> `screens/` 폴더의 HTML 파일들과 `02_디자인시스템.md`를 함께 첨부하세요.

## ▼ 여기서부터

지자체 치매안심센터 담당 주무관이 쓰는 **B2B 관리자 화면**의 시각 디자인을 다시 다듬어주세요.
동작하는 HTML 시안 13장이 이미 있고, 이걸 더 완성도 높은 디자인으로 끌어올리는 작업입니다.

### 제품

**맬리 케어센터** — 인천 남동구 치매안심센터가 주민에게 제공하는 인지건강 앱의 관리자 화면입니다.
어르신 822명이 매일 앱에서 **두뇌훈련 · 재활운동 · 마음다루기** 활동을 하고, 담당 주무관이 이걸 관리하면서
매달 보건소에 제출할 운영 보고서를 만듭니다. 앞으로 다른 지자체에도 판매할 B2B 제품입니다.

### 쓰는 사람

공공기관 담당 공무원입니다. 이 업무는 담당 업무의 **일부**라 하루 종일 이 화면을 보지 않습니다.
아침에 잠깐 열어 "오늘 처리할 게 있나" 확인하고, 월초에 보고서를 만듭니다.
업무용 노트북 **1440×900**, 마우스와 키보드. 모바일은 대상이 아닙니다.

### 첨부한 것

- `screens/` — 화면 13장의 HTML 시안. 브라우저로 바로 열립니다
  - `01`–`11` 실제 화면 · `90` 인터랙션 패턴 정의 · `91` 컴포넌트 시트
- `02_디자인시스템.md` — 색·타이포·간격·형태 토큰과 판단 원칙
- `03_실제데이터.md` — 화면에 들어갈 진짜 숫자와 문자열
- `04_지켜야할것.md` — 바꾸면 안 되는 항목

### 원하는 것

**구조는 유지하고 시각 완성도를 올려주세요.** 화면 구성과 정보 위계는 여러 번 검증한 것이라
정보를 빼거나 화면을 합치지 말고, **보이는 품질**을 끌어올리는 데 집중해주세요.

특히 이런 게 아쉽습니다.

1. **아직 "만든 티"가 납니다.** 요소 하나하나는 규칙을 지키는데, 전체가 하나의 디자인으로 안 읽혀요
2. **여백 리듬이 균일하지 않습니다.** 어디는 답답하고 어디는 비어 보여요
3. **표가 지루합니다.** 12열 표가 기본인데 스캔이 잘 안 돼요
4. **차트와 데이터 시각화가 밋밋합니다.** 히트맵·막대·달력이 다 제각각이에요
5. **빈 상태와 모달이 본 화면보다 완성도가 떨어집니다**

### 목표하는 느낌

**Microsoft Clarity · 토스 비즈니스 · 앱인토스 · 당근비즈니스** 정도의 정돈된 관리자 화면입니다.
셋의 공통점을 이렇게 읽었습니다 — 이 방향을 유지해주세요.

- 페이지 제목이 **크고 굵게** 본문 안에 있고, 상단 바가 따로 없음
- 표를 카드로 겹겹이 감싸지 않음 — 흰 바탕에 헤더 밑줄 하나
- 보조 버튼은 **테두리 없는 회색 채움** (테두리 있는 흰 버튼은 낡아 보임)
- 섹션 사이 여백이 넉넉하고, 표 안은 촘촘함
- 색을 아껴 씀 — 정상 상태는 회색, 색은 주의가 필요한 곳에만

**차분하고 전문적**, 키워드는 **데이터와 체계적인 관리**입니다. 화려하게 만들지 마세요.

### 반드시 지켜야 하는 것

- **키컬러 `#13BD7E`** (맬리브레인 브랜드) — 단, 흰 배경 대비 2.44:1이라 **글자색으로 쓸 수 없습니다.**
  채움색으로만 쓰고 그 위 글자는 `#043528`, 링크·강조 텍스트는 `#077A50`을 씁니다
- **중립색은 초록빛 회색 금지.** 초록 강조색 옆에 초록빛 회색을 깔면 전체가 탁해집니다. 파랑 쪽으로 살짝 기운 회색을 쓰세요
- **글꼴 Pretendard**, 숫자는 `tabular-nums`로 표에서 세로 정렬
- **"참여 중"은 회색.** 822명 중 802명의 기본 상태라 초록으로 칠하면 진짜 위험한 20명이 묻힙니다
- **표 행 높이 52px 유지**, 늘리지 마세요. 12열 × 20행이 한 화면에 들어와야 합니다
- **이름·연락처는 기본 마스킹** (홍*동 / 010-****-1234). 법적 요구사항이라 뺄 수 없습니다
- **달력은 일요일 시작** (일월화수목금토)
- **읽기 전용 화면**(프로그램 일정 · 챌린지)에는 반드시 "변경 요청" 경로를 함께 두세요
- 명도 대비 **4.5:1 이상**, 색만으로 정보를 전달하지 않기 (상태 표시는 점 + 글자)
- 라벨을 명사로 끊지 말고 **문장으로** — "미처리 신청 111건" ❌ / "처리 안 된 신청 · 가장 오래된 건 42일째" ⭕

### 산출물

화면 13장을 각각 아트보드로 만들어주세요. 우선순위는 이렇습니다.

- **A급 (완성도 높게)** — 01 오늘 · 02 참여자 명단 · 03 참여자 상세 · 04 활동 현황 · 05 월간 리포트
- **B급 (A급 패턴 적용)** — 06 상담실 · 07 프로그램 일정 · 08–09 챌린지 · 10 참여 신청 · 11 열람 기록
- **시스템** — 90 인터랙션 패턴 · 91 컴포넌트 시트

빈 상태 · 로딩 · 오류 · 모달도 함께 그려주세요. 이 제품에서 예외는 드문 일이 아니라 일상입니다
(활동 0일인 참여자 198명 = 24%, 대화 없는 상담방 222개 = 36%).

바꾼 부분은 **왜 그렇게 했는지 한 줄씩** 알려주시면 좋겠습니다.
